# 远程控制功能说明

## Windows：RDP over Tailnet

[`启用-RDP-Tailnet.ps1`](启用-RDP-Tailnet.ps1) 用于在 Windows 上自动开启远程桌面，并将 RDP 的入站访问限制在 Tailscale Tailnet 内。脚本完成后会通过 Telegram 发送执行结果和连接方法。

### 使用前提

- 目标机是支持 RDP 主机功能的 Windows 专业版、企业版、教育版或 Windows Server。
- Windows 家庭版、CloudEdition 等不提供 RDP 主机的版本会被脚本拒绝。
- Tailscale 已安装并处于 `Running` 状态，本机已获得 `100.64.0.0/10` 范围内的 Tailnet IPv4 地址。
- 当前用户已能通过 Tailnet 使用 SSH 登录目标机。脚本不会安装 Tailscale，也不会修改 SSH 配置。
- RDP 登录账户必须具有 Windows 账户密码；Windows Hello PIN 不能代替 RDP 密码。

### 脚本会做什么

1. 检查管理员权限；权限不足时自动请求 UAC 提权。
2. 在修改系统前检查 Windows 版本和 Tailscale 就绪状态。
3. 禁用其它明确覆盖 TCP/UDP 3389 的入站允许规则。
4. 创建两条脚本专用防火墙规则：
   - `RDP-Tailscale-TCP`
   - `RDP-Tailscale-UDP`
5. 两条规则都只允许 `100.64.0.0/10` 访问 3389，并适用于所有 Windows 网络配置文件。
6. 把当前 UAC 提权后的 Windows 身份加入“Remote Desktop Users”内置组。脚本通过组 SID `S-1-5-32-555` 定位该组，兼容不同 Windows 显示语言。
7. 开启 RDP，强制使用网络级别身份验证（NLA）和 TLS 安全层，并将监听端口固定为 3389。
8. 将 `TermService` 设为自动启动。如果 RDP 关键配置发生变化，会重启该服务使新配置立即生效。
9. 最后复查注册表、NLA、TLS、服务、防火墙和 3389 监听进程。只有确认 3389 由 `TermService` 持有后才会报告 READY。

### Telegram 通知

Telegram Bot Token 和 Chat ID 位于 PS1 脚本顶部：

```powershell
$TgBotToken = '...'
$TgChatId   = '...'
```

- 配置成功并通过全部就绪检查时，发送 `[RDP READY]`。
- 执行失败或就绪检查未通过时，发送 `[RDP FAILED]` 和原因。
- READY 通知包含主机名、登录账户、Tailnet IP、端口及 Windows/macOS/Linux 客户端连接方法。
- Telegram 投递失败不会回滚已通过就绪检查的 RDP 配置。
- 如果 UAC 在脚本初始化前被取消或阻止，脚本只能在终端报错，无法发送 Telegram 失败通知。

> Bot Token 是敏感凭据。当前项目按源码顶部变量的方式保存，应严格限制脚本和仓库的读取权限；如果可能已泄露，应立即在 BotFather 中重置。

### 运行方法

在 Windows PowerShell 中进入项目目录，执行：

```powershell
powershell -ExecutionPolicy Bypass -File ".\远程控制设置\启用-RDP-Tailnet.ps1"
```

默认在结束前等待按 Enter。自动化调用可使用：

```powershell
powershell -ExecutionPolicy Bypass -File ".\远程控制设置\启用-RDP-Tailnet.ps1" -NoPause
```

返回码：

- `0`：RDP 通过全部就绪检查。
- `1`：配置或就绪检查失败。

### 连接方法

使用 Telegram READY 通知中的 Tailnet IP，例如 `100.x.y.z`。

Windows：

```powershell
mstsc /v:100.x.y.z
```

macOS：安装并打开 **Windows App**，目标地址填写 `100.x.y.z`。

Linux：

```bash
xfreerdp /v:100.x.y.z /u:"COMPUTERNAME\\username"
```

### 幂等性与安全边界

- 脚本可重复运行；专用防火墙规则会被重建为预期状态。
- 脚本不会创建、修改、显示或重置 Windows 账户密码。
- 脚本只会禁用明确将 3389 作为本地端口或端口范围的其它入站允许规则。如果系统存在非常宽泛的 `Any` 端口入站允许规则，脚本不会自动禁用，以免影响其它服务；对有自定义防火墙的机器应另行审查。
- 如果防火墙收紧失败，脚本不会继续开启 RDP。

### 常见失败原因

| 现象 | 原因或处理方式 |
|---|---|
| 提示当前 Windows 版本不支持 | Windows 家庭版等不提供 RDP 主机，需升级系统或改用 NoMachine |
| Tailscale 未就绪 | 检查 `Get-Service Tailscale`、`tailscale status`和 `tailscale ip -4` |
| 无法修改防火墙或注册表 | 确认已接受 UAC 提权，并检查本机组策略或安全软件是否阻止 |
| TCP 3389 未监听 | 检查 `Get-Service TermService`，并查看 Telegram/PowerShell 中的具体失败原因 |
| RDP 提示凭据错误 | 使用 Windows 账户密码，不要使用 Windows Hello PIN；按通知中的完整账户名登录 |
| Telegram 未收到消息 | 检查 Bot Token、Chat ID、目标机外网连通性，以及 Bot 是否被聊天对象屏蔽 |

## Windows：Remote Assistance over Tailnet

[`启用-Remote-Assistance-Tailnet.ps1`](启用-Remote-Assistance-Tailnet.ps1) 是 Windows 上的另一种远程控制方案。它使用系统原生 Remote Assistance 生成受密码保护的 `.msrcIncident` 邀请，将邀请附件和一次性密码通过 Telegram 分开发送。

Remote Assistance 不是无人值守登录：目标机用户必须接受每次连接，并再次确认允许协助方控制鼠标和键盘。

### 使用前提

- Windows 必须提供 `%SystemRoot%\System32\msra.exe`。已移除或被组织策略禁用 Remote Assistance 的系统会直接失败。
- Tailscale 已安装并处于 `BackendState=Running`，本机已获得 `100.64.0.0/10` 范围内的 Tailnet IPv4。
- Telegram Bot Token 和 Chat ID 已作为 `$TgBotToken` 和 `$TgChatId` 字符串直接写在脚本顶部。
- 目标机必须有用户在场处理 Remote Assistance 的接受与控制确认对话框。
- 协助方使用 Windows 打开 `.msrcIncident` 附件。

### 脚本会做什么

1. 自动请求 UAC 管理员权限，校验 Telegram、Tailscale 和 `msra.exe`。
2. 启用受邀式 Remote Assistance 和“可请求完整控制”策略；不启用 Offer/Unsolicited Remote Assistance。
3. 禁用其它明确覆盖 TCP 3389 的入站允许规则，然后创建 `Remote-Assistance-Tailscale-TCP`。
4. 专用规则仅允许 `100.64.0.0/10` 访问 TCP 3389，并应用于所有 Windows 网络配置文件；脚本不创建 UDP 规则。
5. 用加密随机数生成每次不同的 20 位密码，调用 `msra.exe /saveasfile` 创建临时邀请。
6. 检查邀请必须包含当前 `Tailnet-IP:3389`，并确认 TCP 3389 由 `TermService` 进程监听。
7. 先通过 Telegram `sendDocument` 上传邀请，再发送 `[REMOTE ASSISTANCE READY]` 和一次性密码。只有两次交付都成功才返回 `0`。
8. 成功后删除本地邀请文件，保持本次 `msra.exe` 等待连接；任何失败都删除文件并仅终止本次启动的进程。

### Telegram 安全边界

Telegram 聊天同时接收邀请附件和对应密码。因此，**Telegram 聊天访问权限和 Bot Token 都是安全边界的一部分**。凭据以明文存在于脚本和 Git 历史中，任何能读取脚本或仓库的人都能获得它们。应限制聊天成员、脚本和仓库读取权限；Bot Token 如可能泄露，应立即在 BotFather 中重置。

Tailnet-only 防火墙规则仍是网络边界：即使获得邀请和密码，协助方也必须能通过 Tailnet 访问目标机。

### 运行与连接

在 Windows PowerShell 中进入本目录，执行：

```powershell
powershell -ExecutionPolicy Bypass -File ".\启用-Remote-Assistance-Tailnet.ps1"
```

自动化运行：

```powershell
powershell -ExecutionPolicy Bypass -File ".\启用-Remote-Assistance-Tailnet.ps1" -NoPause
```

返回码：

- `0`：本地就绪检查、邀请上传和密码消息全部成功。
- `1`：配置、就绪检查或 Telegram 任一交付失败。

协助方在 Windows 上打开 Telegram 中的 `.msrcIncident` 附件，输入后续 READY 消息中的一次性密码。目标机用户先接受连接；如需操作桌面，再确认允许共享控制。

### 幂等性与常见失败

- 脚本可重复运行；每次重建专用防火墙规则，并使用全新邀请和密码。
- 脚本不创建、显示、修改或重置 Windows 账户密码。
- 如系统缺少 `msra.exe`，请使用现有 RDP 脚本或 Quick Assist。
- 如邀请中没有 Tailnet IP，脚本不会修改未公开的 `.msrcIncident` 格式，而是终止本次邀请并报告 FAILED。
- 如组策略或 MDM 覆盖 Remote Assistance 设置，策略回读检查会失败。
- 如 TCP 3389 未由 `TermService` 监听，检查 Remote Desktop Services 和组策略日志。
- 如 Telegram 只收到附件而未收到密码，本次运行会按失败处理并终止等待进程，请重新运行生成新邀请。

## macOS：Screen Sharing over Tailnet

[`启用-macOS屏幕共享-Tailnet.sh`](启用-macOS屏幕共享-Tailnet.sh) 用于开启 macOS 原生 Remote Management/Screen Sharing。macOS 不提供原生 RDP 服务端，因此该脚本使用系统自带的屏幕共享实现完整桌面远程控制。

TCP 5900 不会直接暴露到 Tailnet 或公网，而是只监听本机 loopback，客户端通过已配置的 Tailnet SSH 隧道连接。

### 使用前提

- 目标机是提供 ARDAgent `kickstart` 工具的 macOS。
- Tailscale 已安装并处于 `Running` 状态，本机已获得 `100.64.0.0/10` 范围内的 Tailnet IPv4。
- 当前普通用户已可以通过 Tailnet SSH 登录目标 Mac。
- 用户必须具有可用的本地 macOS 账户密码。
- 首次使用时，macOS 可能要求在“系统设置→隐私与安全性”中批准屏幕录制或远程管理权限。

### 脚本会做什么

1. 确认运行平台是 macOS，并通过 `sudo` 自动提权。
2. 保存并校验原始非 root 用户的用户名和 UID，防止将远程控制权限授予错误账户。
3. 在修改系统前检查 Tailscale `BackendState=Running` 和 Tailnet IPv4。
4. 检查系统 `kickstart`、`dscl`、`defaults`、`lsof`、`nc` 等必需工具。
5. 先停用旧 Remote Management，枚举并撤销原有用户、UUID 成员和嵌套组授权。
6. 将 Remote Management 收紧为“仅指定用户”，且只授予当前用户屏幕观察与控制权限（`ControlObserve`）。
7. 设置 `VNCLocalOnly=true`，禁用传统 VNC 密码认证，且不创建、显示或重置任何密码。
8. 通过系统 `kickstart -activate` 激活 Remote Management，配置会持久保留并由 macOS 在开机后管理服务启动。脚本本身不会注册为开机任务。
9. 复查偏好设置、ARD 用户组、`naprivs`、监听地址、监听进程和 RFB 协议 banner。
10. 任何就绪检查失败都会强制停用 Remote Management，并确认非 loopback 的 5900 监听已消失后才发送失败通知。

### Telegram 通知

Telegram Bot Token 和 Chat ID 位于 SH 脚本顶部：

```bash
TG_BOT_TOKEN='...'
TG_CHAT_ID='...'
```

- 本地服务、授权、loopback 监听和 RFB 握手全部通过时，发送 `[SCREEN SHARING READY]`。
- 任一配置或就绪检查失败时，发送 `[SCREEN SHARING FAILED]` 和原因。
- READY 通知包含主机、账户、Tailnet IP、SSH 隧道命令和 Screen Sharing 连接地址。
- Telegram 投递失败不会改变已通过安全检查的服务结果。

> Bot Token 属于敏感凭据。两个脚本都按项目约定将其保存在源码顶部，应限制文件和仓库读取权限；如果泄露，应立即在 BotFather 中重置。

### 运行方法

请以需要授权的普通 macOS 用户执行，不要直接切换到 root：

```bash
./远程控制设置/启用-macOS屏幕共享-Tailnet.sh
```

脚本会自动调用 `sudo`。自动化执行可加：

```bash
./远程控制设置/启用-macOS屏幕共享-Tailnet.sh --no-pause
```

### 连接方法

在客户端建立隧道，其中用户名和 IP 使用 READY 通知中的实际值：

```bash
ssh -N -o ExitOnForwardFailure=yes \
  -L 127.0.0.1:5900:127.0.0.1:5900 \
  'username@100.x.y.z'
```

然后在 macOS 客户端执行：

```bash
open vnc://127.0.0.1:5900
```

如果客户端本地 5900 已被占用，可把隧道左侧端口改为 5901，然后连接 `vnc://127.0.0.1:5901`。

### 开机后的行为

- `kickstart -activate` 启用的 Remote Management 配置会持久保留。
- macOS 由系统服务管理器在需要时启动 ARDAgent/Screen Sharing 组件。
- 无需把 SH 脚本自身加入 LaunchDaemon。
- 重启后仍必须先建立 Tailnet SSH 隧道，才能访问只监听 loopback 的 5900。

### 幂等性与安全边界

- 脚本可重复运行，每次都会将 Remote Management 收紧为仅当前用户。
- 重新运行会撤销其它用户原有的 ARD/Remote Management 访问权限。
- 脚本不修改 `/etc/pf.conf`，不直接开放 TCP 5900。
- READY 只表示服务、授权、本地端点和 RFB 协议就绪；macOS 隐私授权仍可能需要用户手动确认。
- 内置 macOS Screen Sharing 客户端是主要支持方式；通用 VNC 客户端可能不支持 Apple 的本地账户认证。

### 常见失败原因

| 现象 | 原因或处理方式 |
|---|---|
| 找不到 `kickstart` | 当前 macOS 不提供所需 ARDAgent 工具或系统组件已被管理策略移除 |
| Tailscale 未就绪 | 检查 `tailscale status`和 `tailscale ip -4` |
| 无法读取或清理 ARD 用户 | 检查本地目录服务、MDM 策略及 sudo 权限 |
| 检测到非 loopback 的 5900 | 脚本会自动停用 Remote Management；按 FAILED 通知继续排查现有屏幕共享或 VNC 配置 |
| 无法获取 RFB banner | Screen Sharing 尚未就绪、被管理策略阻止，或 5900 被其它程序占用 |
| 能连接但黑屏或无法控制 | 在“系统设置→隐私与安全性”中确认屏幕录制和远程管理权限 |
| SSH 隧道建立失败 | 确认使用 READY 通知中的账户和 Tailnet IP，并确认本地 5900 未被占用 |
